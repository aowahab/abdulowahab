# Guest and optional-profile data policy (P1.5)

Version: study-privacy-v1. Product defaults established 2026-11-16; not a statement of legal obligations. Implementation status: policy and pure validation helpers only. No account, export endpoint, deletion worker or storage expiry has been enabled.

## Guest versus profile

Anyone can read published materials and practise without an account. A timed server exam still requires an opaque guest session credential to protect its records and deadlines. Losing that credential loses access; knowing an attempt UUID is insufficient. Profiles are optional and student-specific; existing Admin cookies are not student identity.
Browser-local history remains on that browser/device and may disappear if storage is cleared or unavailable. Show this before an exam. Offer downloadable results and an explicit local-history clear action. Never promise permanent guest storage or automatic cross-device sync.

## Default retention

| Data | Default | Starting event |
|---|---|---|
| Guest server attempts/scripts/results | 30 days | Attempt creation; active jobs cannot silently reset expiry |
| Guest browser history | 90 days, best effort | Local record creation; prune on access |
| Account answer scripts and OCR text | 180 days | Upload creation |
| Account results and learning history | Until user deletion | Explain separately from script expiry |
| Abandoned uploads | 24 hours | Authorization creation |
| Temporary export files | 24 hours | Export creation |
| Operational logs | 30 days | Log creation; exclude scripts, tokens and raw AI prompts |
| Deleted data in backups | At most 30 days target | Backup rotation; verify provider capability before launch |

Use the earlier of parent-attempt expiry, explicit deletion and object retention. Guest expiry overrides a longer script deadline. Downloaded copies remain under the learner's control. Do not promise these expiry times are operating until workers and storage policies are verified. If provider backup limits differ, resolve and disclose before release.

## Export contract

Require a valid owner session for every attempt and script. Export an explicit allowlist: selected attempt metadata, learner answers and released learner feedback. Do not export credentials, private answer keys, unpublished rubrics, other students' information, provider prompts or private storage paths. The helper in shared/study/privacy-policy.js defines the metadata projection; private script downloads are separate authenticated streams, never public URLs.
Use no-store responses and attachment filenames generated by the server. No automatic emailing. Full-account export generation uses an authenticated job and expiring private result, with ownership rechecked at download. Question text/model solutions require publication permissions; a submitted attempt does not grant access to an unpublished paper bank.

## Deletion contract

Provide delete-attempt, clear-guest-history and delete-profile controls. Explain consequences and require one explicit destructive confirmation in the product. Profile deletion requires a current authenticated session and identity recheck; never accept an owner ID as authority.
In a transaction revoke sessions, hide records immediately and enqueue deletion jobs. Stop/lease-fence marking jobs so delayed completions cannot recreate deleted records. Delete scripts, OCR artifacts and temporary exports before dependent metadata; retry idempotently and retain a minimal non-personal deletion receipt. Do not cascade-delete shared materials or paper versions used by other learners. Redact or detach audit ownership as appropriate; erase identifying metadata too. Account identity-provider deletion must be coordinated once a provider is selected. If deletion partially fails, report pending rather than claiming completion. Restoring backups must replay deletion tombstones before access is restored.

## Guest-to-profile transfer

Offer a separate opt-in after sign-in. Prove BOTH the current guest credential and target account session on the server, then transfer in a transaction with stable attempt IDs, an idempotency key and an audit event. Exclude active/uploading/marking attempts until settled. Never merge by email/name alone. Do not move another device's records without its credential.
Server-verified records retain their provenance. Browser-local imports remain explicitly unverified and cannot affect verified readiness or overwrite server marks. Signup and transfer do not silently extend a guest script's retention; offer an explicit retention choice if needed later.
